# URL Shortener API

A simple, CRUD-based URL shortener built with **FastAPI**, **PostgreSQL**, and **SQLAlchemy**.

## Features

- Shorten a long URL into a random 7-character Base62 short code
- Redirect from a short URL to its original destination
- Track click counts per short URL
- Full CRUD support: create, read (single + list), update, delete
- Collision-safe short code generation (checks the database before committing to a code)
- Request/response validation via Pydantic, including strict URL validation on input

## Tech Stack

| Framework | FastAPI |
| Database | PostgreSQL |
| ORM | SQLAlchemy |
| Validation | Pydantic v2 |
| Server | Uvicorn |



## Data Model

| Column | Type | Notes |
|---|---|---|
| `id` | Integer | Primary key |
| `original_url` | String | The long URL provided by the user |
| `short_code` | String | Randomly generated, 7-character Base62 |
| `created_at` | Timestamp | Set automatically by the database (`server_default=now()`) |
| `click_count` | Integer | Defaults to `0`, incremented on each successful redirect |

`short_url` is **not** a stored column — it's computed on the fly (base URL + `short_code`) at response time via a Pydantic `computed_field`, so it never needs to be kept in sync with the domain it's served from.

## API Endpoints

| Method | Path | Description |
|---|---|---|
| `POST` | `/urls` | Create a new shortened URL |
| `GET` | `/urls` | List all shortened URLs |
| `GET` | `/urls/{id}` | Get metadata for a specific URL by internal ID (does not affect click count) |
| `PATCH` | `/urls/{id}` | Update the original URL for an existing entry |
| `DELETE` | `/urls/{id}` | Delete a shortened URL |
| `GET` | `/{short_code}` | Redirect to the original URL (increments click count) |

Interactive API docs are auto-generated by FastAPI and available at `/docs` (Swagger UI) once the server is running.

## Setup

### Prerequisites
- Python 3.12+
- PostgreSQL running locally (or a connection string to a hosted instance)

### Installation

```bash
# Clone the repo
git clone <your-repo-url>
cd URL-shortener

# Create and activate a virtual environment
python -m venv venv
venv\Scripts\activate      # Windows
source venv/bin/activate    # macOS/Linux

# Install dependencies
pip install -r requirements.txt
```

### Environment variables

Create a `.env` file inside the `app/` directory:

```
DATABASE_URL=postgresql://<username>:<password>@localhost/url_shortener
```

### Run the server

```bash
uvicorn app.main:app --reload
```

The API will be available at `http://127.0.0.1:8000`, with interactive docs at `http://127.0.0.1:8000/docs`.

## Design Decisions

**Random short codes over sequential encoding.** Short codes are generated as random 7-character Base62 strings rather than encoding the row's auto-increment ID. This avoids exposing sequential, guessable codes (which would leak how many URLs exist in the system) at the cost of needing a collision check on insert — a deliberate, documented trade-off rather than an oversight.

**Request/response schema separation.** `URLCreate` (input) and `URLResponse` (output) are kept as distinct Pydantic models rather than one shared schema, since the client only ever supplies `original_url` — every other field (`id`, `short_code`, `created_at`, `click_count`) is server-generated and has no place in a request schema.

**PATCH over PUT for updates.** Since only `original_url` is ever meant to be client-editable — and fields like `id`, `created_at`, and `click_count` should never be resubmitted by a client — a partial-update semantic (PATCH) fits this resource better than a full-replacement semantic (PUT).

**No `short_url` column.** The full short URL is derivable from `short_code` and the deployment's base URL, so storing it separately would create a second source of truth that could drift out of sync (e.g., if the app is deployed to a new domain).

## Potential / Future Improvements

- **Authentication and ownership.** Add a `users` table and associate URLs with an owning user, so `GET /urls` returns only the requesting user's links rather than every row in the table.
- **Custom aliases.** Allow users to optionally supply their own short code instead of always generating a random one.
- **Expiration support.** Add an `expires_at` column and return `410 Gone` for expired links instead of resolving them indefinitely.
- **Caching for redirects.** Since redirects are the most frequent, read-heavy operation, an in-memory or Redis cache in front of the `short_code` lookup would reduce database load at scale.
- **Migrations via Alembic.** The schema is currently created with `Base.metadata.create_all()`, which only creates missing tables and cannot alter existing ones. Alembic would allow safe, versioned schema changes going forward.
- **Automated tests.** No test suite currently exists. Pytest coverage for collision handling, 404 paths, and redirect behavior would harden the project against regressions.
